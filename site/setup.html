setup

keep the workspace
lean and reproducible

Four recipes that keep OpenCode fast, cheap on context, and isolated per project — all verified against the actual repo configuration.

01

database maintenance

Sessions live in a SQLite database under the user data dir. It grows without bound; a routine vacuum reclaims pages and a WAL checkpoint keeps the write-ahead log in check.

~/.local/share/opencode/ 
# vacate dead rows — runs online, safe mid-session
sqlite3 ~/.local/share/opencode/opencode.db "VACUUM;"

# how big is the write-ahead log right now?
ls -lh ~/.local/share/opencode/opencode.db-wal

# force a checkpoint and truncate the WAL to zero
sqlite3 ~/.local/share/opencode/opencode.db "PRAGMA wal_checkpoint(TRUNCATE);"
db Do not run these against the repo — the database is per-machine state under ~/.local/share/opencode/, not part of m3j-workspace. The repo keeps it out of git; see the .gitignore section.
02

config compaction

Free-tier context is the scarcest resource. The workspace compacts automatically instead of pruning history: reserved tokens and tail turns keep the recent thread intact while the wall of identical tool output stays away.

The file at the project root, opencode.json, pins the model and sets compaction policy:

opencode.json 
{
  "$schema": "https://opencode.ai/config.json",
  // one provider, one model — the fleet overrides per agent
  "model": "opencode/deepseek-v4-flash-free",

  // per-project skill library, loaded only here
  "skills": { "paths": [".agents/skills"] },

  // primary-agent contract loaded with every session
  "instructions": ["AGENTS.md"],

  // plan + compaction sub-agents stay on the same free model
  "agent": {
    "plan":       { "model": "opencode/deepseek-v4-flash-free" },
    "compaction": { "model": "opencode/deepseek-v4-flash-free" }
  },

  // auto-compact, keep 10k tokens reserved + 2 tail turns
  "compaction": {
    "auto": true,
    "prune": false,
    "reserved": 10000,
    "tail_turns": 2
  }
}
tip The machine-level config at ~/.config/opencode/opencode.jsonc goes leaner — prune: true, tail_turns: 1, reserved: 2000 — and caps tool output at 500 lines / 20 KB. Project policy wins where both apply.
03

per-project isolation

Nothing global leaks into a project. Skills are loaded from the repo, agents are defined next to the code, and the skills stay version-controlled while runtime junk stays out.

skills .agents/skills/ — one directory per skill, each with a SKILL.md. Resolved via skills.paths above, so ~/.agents/ never gets polluted. Archived skills move to .agents/archive/skills/, history kept in git.
agents .opencode/agents/ — one Markdown per agent (frontmatter: description, model, tools, mode; then the body prompt). 15 m3j-* specialists plus ultra-minimal live here.
commands .opencode/commands/finish.md — the /finish gate, dispatched to m3j-sentinel.
gitignore The .gitignore ignores .agents/* then re-includes skills and archive — so skills travel with the repo, and only skills travel.
04

the /finish gate

Before anything merges, a quality gate runs. It is a code-free gate — no build step, just one table to fill (all pass or fail reported, never skipped). Local and CI check the same facts.

01 — sanity no debug junk, no empty/broken files, nothing above 1 MB in the diff
02 — security secret scan, injection patterns, exposed credentials and paths
03 — style naming, no trailing whitespace, no banned font families (per the /finish style step)
04 — quality design-system compliance for site changes; custom cubic-bezier motion only
05 — diff scope creep check — the diff matches the stated intent
06 — verify git status clean, remote in sync, test suite green
07 — ship explicit merge / PR / cleanup verdict with the exact command
local mirror of CI — run before claiming done 
$ bash scripts/validate.sh
== required files ==   ✅ 15/15
== site pages ==       ✅ 5 site/*.html pages
== site nav sync ==    ✅ identical across pages
== rtk filters ==      ✅ schema_version = 1
== summary ==  ✅ PASS — all checks green
gate CI in .github/workflows/validate.yml only checks file presence and nav sync. scripts/validate.sh mirrors it locally — offline, zero deps. Skipping a gate is a human decision, made explicitly.
