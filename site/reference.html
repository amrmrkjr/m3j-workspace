config, paths,
the actual file system

The real contents of the repo's config and ignore files, the paths agents should know, and the map that keeps CI, scripts and the site in sync. No invented keys — everything below was read from disk.

01

project config — opencode.json

Lives at the repo root and is the single source of truth for model, skills, instructions and compaction. Annotated as-is:

opencode.json 
{
  // schema is the contract for the parser
  "$schema": "https://opencode.ai/config.json",

  // default model — every m3j-* agent pins its own
  "model": "opencode/deepseek-v4-flash-free",

  // skills resolve from the project, never ~/.agents/
  "skills": { "paths": [".agents/skills"] },

  // injected into every session
  "instructions": ["AGENTS.md"],

  // sub-hierarchy agents stay free-tier
  "agent": {
    "plan":       { "model": "opencode/deepseek-v4-flash-free" },
    "compaction": { "model": "opencode/deepseek-v4-flash-free" }
  },

  // token economy: compact before you run out
  "compaction": {
    "auto": true,
    "prune": false,      // keep run history in this project
    "reserved": 10000,   // tokens held for the current exchange
    "tail_turns": 2      // most recent turns survive compaction
  }
}
02

global config — the jsonc diff

Machine-level state lives in ~/.config/opencode/opencode.jsonc and applies to every project. The differences from the project file are the point:

autoupdate notify — never auto-download on this machine
default_agent m3j-omniscient — every session starts with the commander
snapshot true — performance tuning for a low-RAM machine
compaction (global) prune: true · reserved: 2000 · tail_turns: 1 · preserve_recent_tokens: 4000
tool_output max_lines: 500 · max_bytes: 20000 — truncate wall-of-text tool dumps before they enter context
permission allow — non-destructive tooling is assumed safe
command preview (serve site via python3 http.server) · status (git status summary)
mcp context7, gh_grep, github, sentry, playwright — registered but all enabled: false; remote ones can flip on per project
references site — the site folder exposed as agent context

.gitignore — as it actually reads

Runtime artifacts stay out; the skill library stays in. The pattern is: ignore everything under .agents/, then explicitly un-ignore the two tracked branches.
