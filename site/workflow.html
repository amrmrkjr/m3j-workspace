ten steps to merge

An end-to-end AI coding pipeline for free-tier models (the m3j-workflow skill). An idea becomes a reviewed, mergeable PR through small phases — one phase per session, one reviewable PR per phase, every gate intact.

01

the pipeline

Steps run in order; each step's done-criterion gates the next. Every step already has an owner and a skill — the pipeline dispatches, it never re-implements.

A new session — no memory of the implementation — reviews the PR. The implementing session never grades its own work.

09
fix / retest loop

Each finding is vetted for technical soundness before fixing, then the acceptance commands and /finish re-run. Findings rejected with reasons recorded.

m3j-executor + m3j-triage
10
human merge gate

Checklist: intended diff only, tests + CI green, review threads resolved, docs match, manual check. Nothing merges without a human saying yes.

human
02

three working files, fixed shape

Live at the project root, seeded from .agents/skills/m3j-workflow/templates/. Sections are fixed — never delete, reorder or rename. One line per item, no essays, every claim checkable. Keep each file under ~200 lines; split a phase that outgrows it.

SPEC.md The contract — what we build and how we prove it. Risky dependencies pinned exactly, no ^ ranges.
ROADMAP.md The phases — ordered by dependency, each shipping as one reviewable PR with a checkable exit criterion.
TASKS.md The executable slices — vertical, phase-tagged, with acceptance command + expected output and a TDD step list that is never skipped.
03

principles

P1 reuse, don't duplicate The fleet and skills already exist for every step. Your job is dispatch order and inputs — never reimplement a covered behaviour.
P2 gates outlive tools Any model can write code. The value is the test-first scaffold, /finish, fresh-context review and the human merge check. Never weaken a gate to save tokens.
P3 small phases only One phase per session, compact handoffs (paths + acceptance commands, never file dumps or history). Token economy is the architecture.
04

free-tier reality

Everything runs on free-tier models, pinned per agent — the pipeline is built around their context budgets, not against them.
